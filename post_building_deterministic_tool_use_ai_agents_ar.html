تصميم الوكلاء الأذكياء محددة السلوك: الجمع بين استدعاء الأدوات والتنفيذ الآمن

📅 2026-11-27 • ⏱️ وقت القراءة: 3 دقائق

💡 أبرز النقاط

  • الفرق الأساسي بين التوليد الحر وتنفيد الوكلاء محدد السلوك عبر استدعاء الأدوات (Tool Use).
  • آلية تصميم مخططات البيانات القياسية (JSON Schema) لضمان صحة المدخلات والمخرجات.
  • تقنيات معالجة الأخطاء الذاتية وتغذية الوكيل بالاستثناءات لإصلاح المسار.
  • تطبيق عملي بلغة بايثون لبناء دورة تنفيذ حتمية تعتمد على المكتبة القياسية فقط.

مدخل إلى التفكير الحتمي في بناء الوكلاء الأذكياء

تعتمد النماذج اللغوية الكبيرة (Large Language Models) في أصلها على التنبؤ الإحصائي بالكلمة التالية، مما يجعل مخرجاتها عرضة للتغير والهلوسة المعرفية. عند بناء الوكلاء الأذكياء (AI Agents) المخصصين للمهام البرمجية والتشغيلية، يصبح التوليد الحر غير كافٍ للوصول إلى نتائج موثوقة. هنا تبرز الحاجة إلى ضبط سلوك الوكيل عبر تقنيات التنفيذ الحتمي (Deterministic Execution) التي تلزم النموذج باتباع قواعد محددة.

يتطلب بناء الوكيل محدد السلوك تحويل استجابات النموذج من نصوص مجمّلة إلى أفعال هيكلية محددة البنية. بدلاً من السماح للوكيل بتخمين الإجابة النهائية مباشرة، يتم تزويده بمجموعة من الأدوات (Tools) المتاحة، ويُطلب منه تحديد الأداة المناسبة وتمرير المدخلات وفق صيغة معيارية، مما يعزل المنطق التوليدي للنموذج عن بيئة التنفيذ الفعلية.

هندسة استدعاء الأدوات وتعيين المخططات البرمجية

تعتمد عملية استدعاء الأدوات (Tool Calling / Function Calling) على تعريف واضحة لكافة الوظائف التي يمكن للوكيل استخدامها. يتضمن هذا التعريف اسم الوظيفه، وصفها الوظيفي، ومخطط البيانات (JSON Schema) الخاص بمدخلاتها. يساعد هذا الوصف الدقيق النموذج اللغوي في فهم متى وكيف يختار الأدوات بناءً على سياق المحادثة.

تكتمل هذه العملية عبر بيئة تنفيذ وسيطة (Execution Runtime). تتلقى هذه البيئة مخرجات النموذج الهيكلية، وتتحقق من مطابقتها لمخطط البيانات المقبول، ثم تقوم بتنفيذ الوظيفة الأصلية في البيئة البرمجية. بعد التنفيذ، يتم إرجاع النتيجة الفعلية إلى النموذج ليعيد تقييم الخطوة التالية بناءً على مخرجات بيئة التنفيذ لا على التخمين.

التعامل مع الأخطاء وإعادة التوجيه الذاتي

لا تخلو استجابات الوكلاء من الأخطاء، سواء تمثلت في تمرير وسائط خاطئة للأدوات أو فشل الأداة نفسها أثناء التنفيذ لأسباب خارجية. يتميز الوكيل الذكي الناجح بقدرته على الاستعادة من الأخطاء (Error Recovery) عبر دورة تغذية راجعة مغلقة (Closed-Loop Feedback).

عند حدوث خطأ أثناء تنفيذ أداة ما، تقوم البيئة الوسيطة بالتقاط استثناء البرمجية وترجمته إلى رسالة خطأ واضحة تضاف إلى سجل المحادثة للوكيل. يقرأ الوكيل رسالة الخطأ في الخطوة التالية، مما يتيح له تعديل الوسائط الممررة أو تصحيح مسار منطق الاستدلال (Reasoning Chain) دون إيقاف البرنامج أو التسبب في إنهائه بشكل غير متوقع.

التطبيق العملي: حلقة تنفيذ حتمية بدون مكتبات خارجية

لبناء فهم عميق لكيفية إدارة هذه الدورة، يمكن محاكاة عمل الوكيل الذكي باستخدام حلقة تنفيذ بسيطة تفصل بين التفكير والتنفيذ. تتولى هذه الحلقة قراءة تعليمات الوكيل، وتحليل طلبات استدعاء الأدوات، وتنفيذها بأمان ضمن بيئة التحكم مع التثبت من صحة المدخلات.

تسمح هذه البنية البرمجية المستقلة بنقل المفهوم إلى أي نموذج لغوي أو واجهة برمجة تطبيقات مستقبلاً، حيث يظل المنطق المحرك مدمجاً في نظام التحكم الخاص بالمطور، مما يضمن أعلى درجات الموثوقية والأمان في الأنظمة الإنتاجية.

🐍 مثال عملي بلغة بايثون

يوضح الكود كيفية محاكاة وكيل ذكي يتخذ قرارات بتنسيق JSON محدد، ثم يقوم المحرك الوسيط بتفسير هذا القرار وتعديل السلوك وتنفيذ الدالة المحددة بأمان مع التعامل مع الأخطاء.

import json
import math

# تعريف الأدوات المتاحة للنظام (Functions Registry)
def calculate_area(radius: float) -> float:
    """حساب مساحة الدائرة بناءً على نصف القطر"""
    if radius < 0:
        raise ValueError("نصف القطر لا يمكن أن يكون سالباً.")
    return math.pi * (radius ** 2)

TOOLS = {
    "calculate_area": calculate_area
}

# محاكاة محرك الوكيل الذكي (Agent Execution Core)
def mock_llm_decision(user_input: str) -> str:
    """محاكاة مخرجات النموذج الهيكلية (JSON Tool Call)"""
    # في التطبيق الفعلي، هنا يتم استدعاء نموذج اللغة
    if "مساحة دائرة" in user_input:
        return json.dumps({
            "tool": "calculate_area",
            "arguments": {"radius": 5.0}
        })
    return json.dumps({"error": "لم يتم التعرف على الأداة المناسبة"})

def run_agent_step(user_query: str):
    print(f"الطلب: {user_query}")
    
    # 1. الحصول على قرار الوكيل
    raw_response = mock_llm_decision(user_query)
    decision = json.loads(raw_response)
    
    # 2. التحقق من صحة القرار وتنفيذ الأداة بحتمية
    tool_name = decision.get("tool")
    if tool_name in TOOLS:
        try:
            args = decision.get("arguments", {})
            result = TOOLS[tool_name](**args)
            print(f"[نجاح التنفيذ] الأداة: {tool_name} | النتيجة: {result:.2f}")
        except Exception as e:
            print(f"[خطأ في التنفيذ]: {e}")
    else:
        print(f"[خطأ]: {decision.get('error')}")

# تشغيل تجريبي للوكيل
if __name__ == "__main__":
    run_agent_step("احسب لي مساحة دائرة نصف قطرها 5 سم")
